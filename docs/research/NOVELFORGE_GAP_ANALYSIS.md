# NovelForge AI 现状差距分析与十大改进能力 (NOVELFORGE_GAP_ANALYSIS.md)

- **评估日期**：2026-10-14
- **当前版本**：NovelForge AI V2.2
- **目标版本**：NovelForge AI V2.3

---

## 1. 现状差距深度分析 (Gap Analysis)

虽然 NovelForge AI 在数据层（8 层结构体系、M:N 剧情矩阵、SQLite FTS5 长期记忆）、工作台层（V2.1 Docking 自由拖拽停靠）和基础运维（V2.2 自动更新与热备份）上构建了极其扎实的底座，但对照成熟小说创作软件与先进开源推演架构，在**“直接服务长篇小说作者日常写作心流”**的业务层面仍存在以下 5 大核心断层：

1. **专项工具箱孤岛断层**：
   - 现状：现有 AI 面板主要提供通用的“顺势续写”、“场景五感”等操作，没有覆盖从“起名、简介、黄金开篇、金手指设计、力量体系、分卷策划、单章细纲、对话精修”等垂直场景；
   - 痛点：生成的内容多在临时预览框中展示，缺乏一键“正式接受存为章节”、“正式沉淀为角色卡”、“存为世界观规则”的实体资产关联闭环。
2. **生产流水线（工作流）黑盒断层**：
   - 现状：当前的自动连载引擎虽然具备 `SerializationJob` 状态机，但在底层是固化代码串联（先细纲、再作家、再审稿、再沉淀记忆），作者无法像星月写作那样自由定义属于自己的创作工作流（例如：“先生成两个备选大纲 -> 人工选择一个 -> 生成 3 个核心人设 -> 生成第 1 卷细纲 -> 写第 1 章正文”）；
   - 缺少直观的分步执行与中间编辑能力。
3. **设定集手动精准挂载断层**：
   - 现状：后台虽然有强大的五层记忆引擎（L0~L4）在自动切片装配上下文，但用户缺少在界面上自主勾选“本章我要关联【主角】+【大反派】+【宗门禁忌规则】+【上一章正文】”的直观控制手柄。
4. **提示词产品化与题材库断层**：
   - 现状：目前提示词集中在 `prompts/` 文件夹的静态 markdown 中，作者无法在界面中按“修仙/玄幻”、“都市/神豪”、“科幻/末世”、“悬疑/惊悚”等流派切换预设，无法自定义变量插槽。
5. **文风档案与审稿仲裁闭环断层**：
   - 现状：审稿报告产出了详细评分与发现，但缺乏“一键采纳修订生成版本差异”与“标记误报/忽略”的交互闭环；缺乏针对作者个人独特文风的系统性建档。

## 2. 梳理出的十大高价值改进能力候选

| 序号 | 改进能力名称 | 借鉴来源 | 核心解决痛点 | 预估复杂度 | 优先级建议 |
| :---: | :--- | :--- | :--- | :---: | :---: |
| **C01** | **一体化小说专项工具箱 (Novelist Toolbox)** | 星月写作 | 提供起名、简介、脑洞、金手指、力量体系、黄金开篇、章纲拆解等垂直生成器，结果一键入库为实体资产 | 中等 | **P0** |
| **C02** | **可配置小说创作工作流引擎 (Workflow Engine)** | 星月写作 | 支持自定义步骤、变量传递、分步执行/一键执行、断点保存与用户原地编辑 | 中高 | **P0** |
| **C03** | **设定集显式关联与上下文选择器 (Context Picker)** | 星月写作 | 在创作/工作流各节点提供角色卡、世界观词条、历史章节与备忘录的快捷勾选挂载 | 低 | **P0** |
| **C04** | **提示词工作室与题材流派预设 (Prompt Studio)** | 星月写作 + 本地设计 | 提供仙侠/都市/科幻等多流派模板、变量插槽管理、多模型适配与自定义提示词 | 中等 | **P1** |
| **C05** | **因果义务链与承载力推进 (Causal Obligation Beats)** | novel-studio | 前章生成的明确后果事件，强制作为下一章场景规划的前置原因消费，严防剧情悬浮漂移 | 中等 | **P1** |
| **C06** | **有界重渲染与熔断配额 (Bounded Realization & Quota)** | novel-studio | 限制单章 AI 重写次数上限（如最多 3 次），避免死循环消耗与失控费用 | 低 | **P1** |
| **C07** | **作者文风档案建模 (Voice Profile Studio)** | Novel Engine | 通过风格问答或代表作片段分析提取作者句式、张力、视角，注入 System Prompt 杜绝 AI 译制腔 | 中等 | **P1** |
| **C08** | **审稿仲裁闭环与版本差异合并 (Review Arbitration)** | novelforge | 审稿发现支持“一键采纳生成正文差异 Diff”与“标记误报/忽略” | 中等 | **P1** |
| **C09** | **多 Agent 独立模型与端点网关绑定 (Per-Agent Model Gateway)**| 综合架构 | 允许为主编、编剧、作家、审稿、记忆管理员独立指定不同的模型提供商与参数（如作家用 DeepSeek，审稿用 Claude） | 中等 | **P2** |
| **C10** | **Docking 工作台专项创作预设拓展 (Creative Workspace Presets)**| 本地工作台深化 | 在已有的 Docking 20 面板基础上，增加“工作流编排”、“专项生成器”、“文风调校”等专属面板与预设布局 | 低 | **P2** |
