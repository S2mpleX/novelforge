## 1. 目标概览

### 1.1 闭源商业产品：星月写作
- **官方网址**：`https://xingyuexiezuo.com/`
- **定位**：面向网络文学作者的 AI 辅助写作与全流程生成平台。
- **调研范围**：
  - 官方网站公开介绍、功能列表、帮助文档、操作指南与公开演示案例；
  - 重点调研小说专项生成器体系（书名、简介、大纲、细纲、正文、续写、润色等）；
  - 调研设定集管理、知识库关联与上下文挂载逻辑；
  - 调研提示词系统的分类、变量注入与场景化模板交互；
  - 记录工作流各步骤的点击跳转成本与交互闭环机制。
- **本地客户端资产状态**：检查用户当前工作区或环境是否挂载星月写作本地安装包。经检索目前本地尚未提供其 Windows 客户端离线安装程序，优先从公开 Web 端及官方文档切入，严密标记事实与推断。

### 1.2 开源项目 A：novel-studio
- **仓库地址**：`https://github.com/Xiaoyangy/novel-studio`
- **核心定位**：基于多 Agent 自主协同的长篇小说自动化创作与推演系统。
- **重点审查机制**：
  1. 多 Agent 职责划分与角色定义；
  2. 结构化 JSON Schema 消息通信；
  3. 世界状态推演引擎与小说事实更新；
  4. 长期记忆 RAG 检索逻辑；
  5. 章节任务流水线与状态推进；
  6. 断点恢复与 Token 消耗控制。

### 1.3 开源项目 B：novel-engine
- **仓库地址**：`https://github.com/john-paul-ruf/novel-engine`
- **核心定位**：AI 编辑室理念驱动的端到端小说写作工作流引擎。
- **重点审查机制**：
  1. 编辑团队角色分工（总编、架构师、情节编辑、审稿员）；
  2. 从创意构思、人设世界观到成稿的管道；
  3. 作者风格/文风档案（Style Profile）的提取与约束；
  4. 审稿修订流水线与差异对比；
  5. 许可证条款与模块独立性。

### 1.4 开源项目 C：novelforge (参考仓库)
- **仓库地址**：`https://github.com/sheengoa/novelforge`
- **核心定位**：现代小说创作工作台与导演式（Director）AI 对话系统。
- **重点审查机制**：
  1. 现代富文本/分章编辑器体验；
  2. Director 对话与正文/实体的双向同步；
  3. 人物档案、世界观卡片与章节实体的关联存储；
  4. Agent 评审建议的版本仲裁与人工接受/拒绝闭环。

### 1.5 现有基线系统：NovelForge AI (本项目)
- **工程位置**：`e:\小说`
- **核心技术栈**：Tauri 2 + Rust + React 19 + TypeScript + SQLite WAL + Tiptap + Tailwind CSS v4 + React Flow。
- **优势能力**：8 层内容层级架构、M:N 独立剧情关系矩阵、五层长期记忆（L0~L4）、可拖拽停靠工作台、应用内无缝自动更新与灾备恢复。
- **待攻克短板**：
  1. 缺乏一站式“小说专项生成器工具箱”（现有 AI 助手仅为右侧面板的若干简单动作与自由对话，未能与书籍全流程设定结构化深度互联）；
  2. 缺乏可视化的创作工作流（从构思 -> 人设 -> 规则 -> 大纲 -> 细纲 -> 正文 -> 审校的一体化推进缺少编排引擎）；
  3. 提示词未实现“题材/流派库”、“模型偏好”与“动态变量槽位”的产品化管理；
  4. 知识库/权威事实的实时关联目前较多依赖后台自动上下文装配，用户缺乏精细化挑选“特定人物/特定伏笔/特定历史章节”作为参考的手动交互界面。
