# 星月写作可观察技术架构分析 (observable-architecture.md)

- **研究日期**：2026-10-14
- **证据级别**：静态前端 Bundle (`index-4d14a7b1.js` 等) 逆向与网络拓扑观察

---

## 1. 前端技术栈与客户端形态

1. **框架体系**：
   - Vue 3 + Vue Router (`/workflow/list`, `/chapters/:id`, 等)；
   - Capacitor (`vendor-capacitor-100ee7d1.js`)，用于构建 Web/iOS/Android/桌面跨端；
   - 样式引擎：Tailwind CSS / 原子化 CSS。
2. **状态与持久化**：
   - 用户配置保存在 `localStorage.getItem("appSetting")`；
   - 包含主题 (`eye-care`, `dark`, `star-moon`) 与编辑器皮肤；
   - 业务数据（小说、章节、设定、工作流）主要托管在云端后端。

---

## 2. 工作流执行拓扑与数据流转

```
[用户配置工作流]
      │
      ▼
[工作流实例化 (runId)] ───► [云端工作流引擎 / 队列调度]
      │                               │
      ▼                               ▼
[前端分步渲染卡片] ◄── [SSE 流式长连接 (模型输出推演)]
      │
[用户原地编辑修订] ───► [提交 Step Patch] ───► [注入下游变量 Context]
```

### 2.1 依赖拓扑管理 [INFERENCE]
- 前端定义各步骤的输入依赖关系。若 Step 3 依赖 Step 2 的输出，当 Step 2 处于完成状态时，Step 3 自动变为“待执行”；
- 失败重试时，通过断点快照保留已完成的 Step 1~2 输出，仅重试失败的 Step 3。

---

## 3. 对比 NovelForge AI 的可借鉴点与差异

1. **星月写作优势**：
   - 高度成熟的“工作流 (Workflow)”产品化，将复杂的 AI 提示词和长篇规划封装成傻瓜式“一键执行 / 分步执行”卡片；
   - 显式设计了【关联角色】、【关联词条】、【关联章节】的设定选择器。
2. **星月写作短板与受限点**：
   - 云端 SaaS 依赖，受限于网络与云端算力；对创作者极其敏感的书稿和核心大纲存在云端隐私泄露风险；
   - 模型受制于平台统一分配或扣点扣字数收费；
   - 面板不可自由拖拽停靠，缺乏多窗口并行推演与专业桌面创作环境。
3. **NovelForge AI 优势**：
   - 纯本地优先，SQLite WAL 存储与 FTS5 毫秒检索，数据 100% 掌握在作者本地；
   - 拥有真正的 8 层小说内容体系、M:N 独立剧情矩阵与五层长期记忆引擎；
   - 具备专业级 Docking 可拖拽停靠工作台与无缝应用内自动更新。
