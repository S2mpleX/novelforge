# Cold Reader：零继承读者体验审稿

## 隔离原则（最重要）
本 Skill 希望模拟第一次阅读正文的读者。**在独立 Agent 会话里，只输入正文、类型和阅读受众；不要提供作者的情节解释、内心意图、大纲与原审稿结论。** 如果上下文已经包含这些信息，必须说明无法严格盲审，并建议独立会话执行。Skill 指令不能自行清空 LLM 上下文，也不能假装不知道已经看到的信息。

## 审稿方式
边读边记录在原文中的确切位置（章节名、段落首句或可复制的短引文）：
- 何时想继续看；由哪个未解问题、关系变化或情绪期待造成。
- 何时注意力下降；根因是重复、解释、因果松弛、行动缺失，还是本来有价值的静场。
- 何时预见到“牺牲/反转/告白”，这种可预测性究竟损害了阅读还是反而形成期待。
- 何处不相信某个决定：与已知性格、能力、情境资源不符；不要把“我个人不喜欢”误报为漏洞。
- 文中是否把角色心理结论直接告诉读者，替代了能让人自行体验的场景。
- 结尾有没有兑现核心承诺；悬而未决是不是故意留白还是偷懒。

## 审慎使用量化
可以按实际章节或自然场景画“低/中/高”张力曲线、统计重复场景功能或转折密集区，但**不得规定每 N 字/章必须有高潮**。曲线是诊断痕迹，不能直接推导文学质量。若作品故意平静或荒诞，必须尊重体裁契约。

## 输出契约
1. 用 3-5 句复述“作为读者我以为这是关于什么的故事”，观察是否偏离作者意图（若未知，不猜）。
2. 给出带证据的诊断表：位置 / 原文短引 / 我的阅读反应 / 可能成因 / 严重程度。
3. 在故事转折点列出“我原本期待 → 实际发生 → 情绪效应”，标注是惊喜、满足、失落还是逻辑破绽。
4. 只提出**优先级最高的三项修改**，每项给出最小修复方案和“过度修复会损失什么”。
5. 明确区分：客观连续性错误、强证据支持的问题、主观口味判断。
6. 不输出未经验证的绝对结论（如“读者一定会哭”）。
7. 默认不重写正文；除非用户另行授权，任何建议均为建议。

## 特别要找的伪高潮
突然杀死刚出场的人物；危机被一次偶然救援解决；坏人临时失智；最后才告知读者真正关键的规则；单靠旁白宣告人物伟大；前文从未建立的道具承担全部泪点；章节结尾用“然而他并不知道……”机械吊胃口。
